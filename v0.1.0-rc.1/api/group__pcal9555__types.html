◆ Error

enum class pcal9555::Error : uint8_t
strong

Why a call failed. Every call of the driver returns one of these in its Result.

Values 0 to 9 are the shared base set; chip-specific values start at 16. The chip has no timed operation, no CRC, no busy state and no fault flag, so Timeout, Crc, Busy and DeviceFault are never returned. The type is [[nodiscard]]: a call whose Error is dropped does not compile without a warning (handbook KB-CPP20-037).

Enumerator
Ok 

The call succeeded.

NotInitialized 

EnsureInitialized() has not succeeded yet, or Deinitialize() ran since, or a call found the chip reset (DeviceReset).

InvalidArgument 

An argument, the address or a Config field is out of range; nothing was sent.

Bus 

A port hook returned false: a bus error, a NACK of a data byte, or a NACK the port cannot place. A port without the optional GetLastFailure() hook reports an absent chip as Bus too.

Timeout 

Not returned by this driver (the chip has no timed operation).

DeviceIdMismatch 

At start-up, something answers at the address but is not the configured part: a register read back differently after EnsureInitialized() wrote it, or a reserved bit of the PCAL9555A output port configuration register read 1.

Crc 

Not returned by this driver (I2C transfers carry no CRC).

Busy 

Not returned by this driver (the chip has no busy state).

DeviceFault 

Not returned by this driver (the chip reports no faults).

Unsupported 

An Agile I/O call or Config field on a driver configured for the PCA9555 (Variant::Pca9555).

WriteMismatch 

After start-up, a register read back differently from what was just written: the chip acknowledged the write but did not keep it (a write dropped on a noisy bus). Pin calls only with Verify::ReadBack; ApplyConfig() always.

NoDevice 

Nothing acknowledged the address byte: no chip at the address, or it is unpowered. Needs a port with the optional GetLastFailure() hook, which tells an address NACK from other failures; without it this is Bus.

DeviceReset 

A running driver found the chip back at its power-up values: a supply dip below the power-on reset voltage reset every register (section 6.4, table 4). Nothing was written; the driver is uninitialised, so call EnsureInitialized(), which writes the copy again in order. A write to the checked register that the chip dropped reads the same way.

enum class pcal9555::Variant : uint8_t

Which part is on the bus. The driver does not detect it: the data sheets do not say how a PCA9555 answers a command byte it does not implement, so probing the Agile I/O bank is not safe.

Enumerator

◆ Verify

enum class pcal9555::Verify : uint8_t
strong

Whether a pin call reads back what it wrote, chosen per call (the last parameter of every pin and Agile I/O setter).

The data sheet needs only the write, so that is the default. ReadBack costs one more I2C read per register written (a 2-byte read after each pair, 1 byte after 0x4F), which more than doubles the call's bus time. It catches a write the chip acknowledged but did not keep (a write dropped on a noisy bus), which ReadInputs() cannot show for an output pin, and returns Error::WriteMismatch for it. EnsureInitialized() and ApplyConfig() always read the whole configuration back.

Enumerator
None 

Write only. Default.

ReadBack 

Write, then read the register back; a difference is Error::WriteMismatch.
